# DirectX 11 Weighted Blended OIT benchmark

This standalone Windows experiment compares three transparency paths inside the same interactive 3D scene:

1. Unsorted conventional alpha blending
2. CPU object-center back-to-front Z sorting
3. Weighted Blended Order-Independent Transparency

All terrain, sky, particles, and crossing geometry are generated by code. The project does not contain or redistribute Mabinogi Mobile assets.

## Purpose and limits

The experiment measures whether WBOIT reduces sensitivity to transparent submission order and what CPU and GPU cost it introduces. It does not prove behavior inside the original game project, so results must be described as independent synthetic benchmark data.

## Architecture

```text
wWinMain
  -> MainApp
    -> ApplicationContext
      -> InputManager
      -> CameraManager -> FreeCamera
      -> SceneManager  -> WorldScene
      -> BenchmarkManager
      -> Renderer
```

Game objects are thin composition roots:

- `FreeCamera` combines Transform, Camera, and FreeCameraController components.
- `Terrain` combines Transform and procedural Mesh components.
- `SkyBox` contains only a sky data component.
- Each scene uniquely owns SkyBox and Terrain through `WorldScene`.
- Renderer receives `SceneRenderView` and does not own or call game objects.

Context-owned managers, scenes, and the active camera use explicit `std::unique_ptr` ownership. Direct3D resources use `Microsoft::WRL::ComPtr`. Components whose lifetime matches their game object are stored by value.

## 3D scene and controls

- `WASD`: move the perspective camera
- Hold right mouse button: look around
- `Q` / `E`: move vertically
- `F1` / `F2`: crossing validation / particle stress scene
- `1` / `2` / `3`: unsorted alpha / object-center Z sort / WBOIT
- `+` / `-`: change instance count
- `R`: reverse submission order
- `P`: save a BMP under `reports/local/windowed`
- `B`: run the automated benchmark
- `Esc`: exit

The scene contains a procedural directional sky, a generated height terrain with depth testing, world-space crossing geometry, and camera-facing particle billboards.

## WBOIT formula

```text
alphaWeight = pow(max(alpha, 0.001), pAlpha) * kAlpha
depthWeight = exp(-(1 - saturate(zNdc)) * kDepth)
weight      = alphaWeight * depthWeight
```

Defaults are `pAlpha=1.8`, `kAlpha=6.0`, and `kDepth=2.5`.

## Build and run

```powershell
& 'C:\Program Files\Microsoft Visual Studio\18\Community\MSBuild\Current\Bin\MSBuild.exe' `
  .\Dx11WboitBenchmark.sln /m /p:Configuration=Release /p:Platform=x64

.\x64\Release\WboitBenchmark.exe
```

The automated run writes `reports/local/windowed/windowed_benchmark.csv`. GPU timestamps include sky, terrain, and transparency rendering but exclude swap-chain presentation. The current 3D reference timing is stored in `reports/reference/2026-09-02-rtx5060-3d`.

## Reference result warning

`reports/reference/2026-09-01-rtx5060` was collected by the earlier screen-space implementation. It remains historical evidence but is not a current measurement of this 3D scene. New portfolio numbers must come from a fresh automated run.

Object-center sorting is not a ground-truth solution for intersecting transparent geometry. WBOIT is an approximation and can change color accumulation. Portfolio material should include hardware, resolution, sample count, scene and camera state, performance cost, and forward-versus-reverse visual evidence. PIX or RenderDoc is still required before extending the claim to the original game pipeline.
